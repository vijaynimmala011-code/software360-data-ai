# Software Security Policy

> **Fictional training document.** All organizations, people, rules,
> thresholds, dates, costs, contacts, and examples are invented for Software
> 360. This is not an operational company policy and contains no confidential
> information.

## 1. Purpose and scope

This policy establishes fictional minimum security expectations for software
tracked by Software 360.

## 2. Approved software use

Users access only approved products through governed assignments. Unapproved
software is not treated as authorized merely because activity is observed.

## 3. Data handling

Restricted or confidential data must not be placed in an unapproved product.
Synthetic training data is used for demonstrations and automated tests.

## 4. Access and secrets

Access follows least privilege. Passwords, tokens, connection strings, and
local `.env` files must never be committed to source control or embedded in
documents.

## 5. Monitoring and incident response

When suspicious activity is detected, responders preserve fictional evidence,
revoke affected access, record timestamps, and notify the designated role
owners without copying secret values into tickets.

## 6. Exceptions and periodic review

Security exceptions have an owner, scope, compensating control, and expiration
date. Reviews occur on a fictional quarterly schedule.
