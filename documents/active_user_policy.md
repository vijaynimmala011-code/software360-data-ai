# Active User Policy

> **Fictional training document.** All organizations, people, rules,
> thresholds, dates, costs, contacts, and examples are invented for Software
> 360. This is not an operational company policy and contains no confidential
> information.

## 1. Purpose and scope

This policy defines qualifying software activity for fictional monthly
utilization reporting.

## 2. Active user definition

A user is active when the user performs at least one qualifying interaction
during the reporting month. Login-only events do not qualify unless a
fictional product contract explicitly defines them as usage.

## 3. Qualifying and excluded events

Viewing, editing, exporting, messaging, and meeting activity may qualify.
Automated health checks, duplicate events, and invalid negative durations are
excluded from the numerator.

## 4. Assignment eligibility

Activity counts only while the user has an active software assignment. Events
with a missing software identifier are quarantined until corrected.

## 5. Reporting grain

Utilization is reported by organization, software product, and month. The
numerator is distinct active assigned users. The denominator is distinct users
assigned during the month.

## 6. Late data and corrections

Late-arriving events trigger a deterministic recalculation of the affected
month. Corrections retain an audit record of the original and revised result.
